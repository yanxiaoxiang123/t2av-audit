# T2AV 实际检查与证据边界

## 评分边界

- 以实际模型输入 Prompt 为准。7 个通用指标 VQ、AE、VF、AQ、AF、AV、TS 始终评分；10 个条件指标 DC、LS、TX、PH、MU、PR、SB、HM、MT、PS 仅在 Prompt 明确涉及时启用。生成结果缺失要求内容时仍属已启用，不能改成“不适用”。
- 仅使用 [rubric.md](rubric.md) 的 0–5 整数锚点，`overall_score=null`。0–2 分填写具体失败原因；所有分数都引用已保存证据。
- 视觉不确定性遵循严格阻断：关键实体、部件或状态无法连续对应时，不得推定一致，按 [state_transition_protocol.md](state_transition_protocol.md) 标记 `uncertain` 并应用分数上限。普通审美偏好或无关模糊不能制造缺陷。
- 静态场景也分别检查主体身份、数量、属性和空间绑定。动态过程不能只看最终帧。
- 不能因为正常不可见的内部机构而自动扣分；先定义 Prompt 所要求的可见接触、动作与状态变化。不能用无关主体的正常动作证明目标交互，也不能用遮挡笼统解释已出现的可见结构矛盾。

## 视觉证据

- 全片至少按源 PTS 做 4-fps 概览覆盖；接触、交接、遮挡、快速运动、切镜、口型、文字变化和同步事件使用局部高密度检查。严格物理动作按状态转换协议提取全部源帧。
- 当前审核模型必须实际查看图像。概览缩略图仅用于发现事件；小物体、文字、手物接触、几何、口型和结构结论须有原像素证据。连续中间帧可按 native_board 协议检查，前/中/后关键原图和有歧义的原图仍需单独打开。
- 每个视觉证据帧保存源帧号、PTS、原图路径、尺寸和真实位置框。框坐标为原图 `[left, top, right, bottom]`；异常用红框、满足项用绿框。不存在的对象不画对象框，可用全帧 `search_area` 表示搜索范围。
- 动作、因果、同步和结构跳变使用前/中/后序列；单帧不能证明动态关系。所有引用文件先保存并重新打开核验。

## 音频与联合证据

- AQ 始终评价实际音轨质量。AF 只评价 Prompt 明确提出的声音、对白、音乐或声效要求；Prompt 没有明确音频要求时，不得因画面动作通常“应有”自然声而降低 AF。
- AV 只检查音频证据已确认存在的声音与实际视觉事件之间的关系。不能从视觉动作反推声音存在，也不能把通用音频分析未提及某事件当作已确认缺失。
- DC、LS、MU、PR、SB、MT 仅按 Prompt 显式启用。LS 不用于画外音；TX 仅在 Prompt 对文字内容、可读性、样式、位置或时序有明确要求时启用。
- 使用 `analyze_audio.py` 保存的原轨 WAV、源时间映射、分析结果与哈希。Gemini 输出是候选证据，`verified_by_listening=false`，除非当前审核者实际播放并听取。关键请求事件未被通用分析覆盖时，使用 `--start/--end/--focus` 定向复核；仍不明确则记录不确定性。
- 冻结计划中的每个音频或对白要求须运行 `audio_review.py RUN --output-dir RUN/audio/requirements`。它保存全段与局部音频复核、PCM 瞬态候选、类别/数量/存在性冲突、时间冲突和待听片段。PCM 只定位候选窗口，不证明枪响、金属撞击或任何声源语义。分开记录声音/台词是否可辨、音频侧数量或禁令是否满足、估计时点是否一致、以及与画面是否绑定。全段和局部都找到同一声音或台词时，单纯 onset 估计不同应保留 `audibility_status=confirmed_present`，同时设 `timing_status=conflict`；若全段与局部或相互重叠的局部估计差值超过 `max(0.5 秒, 双方报告的不确定度之和)`，进入时间冲突，不能将其扩散为声音缺失或台词内容不确定。全段与局部对声音存在、具体类别或数量有实质矛盾时，标 `uncertain` 并进入试听队列。全段描述未提及某声音不能证明缺失；只有全段与覆盖相关时段的局部检查均明确报告缺失，且没有遮蔽或内容冲突，才可写“未呈现”。
- “声音存在”“Prompt 数量/禁止条件满足”和“声画/镜头绑定”是三个独立判断；例如听到两声枪响不能满足“恰好一声”，没有音乐可以满足“禁止配乐”。音频侧 `fulfillment` 不代表 Shot1/Shot2 等视觉绑定已成立。检查 shot-bound 需求时，用 `timing_estimates` 的源时间与视觉切点 PTS 作粗粒度比较：各估计均落在同一镜头内时，可记录镜头级绑定而不宣称精确同步；估计落在不同镜头或跨越切点不确定区时，绑定保持 `无法判断`。已解决或确认矛盾的绑定在最终 `prompt_checks[]` 中写 `audio_binding`，列出绑定状态、所用音频估计、视觉区间、理由及证据引用。
- `listening_clips` 是按 WAV 去重并按冲突优先级排序的试听入口；`listening_queue` 保留逐要求映射。即使声音内容已确认，只要时间估计冲突，也要保留对应局部片段。`uncertain` / `analysis_failed` 对应 `无法判断`；时间绑定未解决时，相关 AV/时序指标使用低置信并写明限制。网关失败可用 `--resume` 续跑，成功批次会按哈希复用。
- AV/LS/SB 的声画时间必须基于同一源时间轴。`offset_sec = audio_time_sec - visual_time_sec`；音频起点须落在所引 WAV 的源时间区间，视觉起点须有相邻 0.25 秒内的源帧支持，并且总不确定度不超过 0.1 秒。无法满足时填 null，不虚报精度。

## 证据完整性

- 每个数值评分至少引用一项真实证据。全局质量和满分结论需要覆盖全片的代表证据，不能由单个好帧推出。
- 音频相关评分必须引用实际 WAV 或经验证的无音轨探测日志；视频帧只能提供时间上下文。
- 区分“源证据不存在”和“工具未提取成功”。解码或网关失败属于检查限制，不能冒充内容缺失。
- `viewed_frame_indices`、`original_frames_opened`、音频听取范围、分析范围和工具日志必须记录实际完成情况，不得填写计划范围。
- 三个冻结检查点和其资产哈希必须保持不变。最终 draft 只能引用冻结事实，不能为了适配分数新增相反观察。
